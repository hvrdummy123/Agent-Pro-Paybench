# PayBench Design

## Pitch

PayBench is a **simulated, deterministic payments world** that measures whether LLM agents can safely operate a payments back office: lookups, refunds, transfers, disputes, policy compliance, and recovery from ambiguous API faults — without following prompt injections.

## Architecture

```
Agent ──tool calls──▶ Harness ──▶ World (sim) ──▶ Graders + Taxonomy
                         │
                         └── traces → metrics → leaderboard site
```

### Simulator (`src/paybench/sim/`)

- **Money**: integer minor units only.
- **Clock**: virtual time from fixed epoch; tools advance it; `wait` for backoff.
- **Rng**: seeded with named independent sub-streams.
- **Ledger**: double-entry; balances derived; invariants I1–I5.
- **World**: entities + case log + idempotency store + `state_hash()` + snapshot/restore.
- **Tools**: JSON in/out; faults injected deterministically; policy mostly graded, not blocked.
- **Faults**: clean / flaky / hostile profiles + targeted rules (timeout-after-commit is the headline trap).

### Tasks & grading

- ~50 tasks across lookup, ops, disputes, policy, faults, adversarial, long-horizon.
- Graders inspect **final world state + case log**, never assistant prose (except honesty of `finish`).
- Oracle gold traces must score 100%; Naive must fail traps; mutation tests prove grader strength.

### Harness

- Model-agnostic tool loop; provider adapters; cost accounting from `pricing.yaml`.
- Baselines: Oracle, Null, Random, Naive, MockLLM.
- Resumable runs, replay with state-hash verification.

### Analysis & site

- Metrics: pass@1, pass^k, safety-violation rate, cost/success, recovery rate.
- Failure taxonomy F1–F15 from traces.
- Static HTML leaderboard generated by Python (no Node).

## Non-goals

Real payment rails, real money, real PII, LLM-simulated customers.
